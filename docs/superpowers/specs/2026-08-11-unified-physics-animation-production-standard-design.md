## 2. 重整目标

本轮只重整项目规范，不批量改造旧动画。新规范完成后立即适用于所有新建、改版和修复任务；未进入修改范围的旧动画暂不处理，在下次改版或修复时增量迁移。

本轮解决以下问题：

1. 总提示词、`AGENTS.md`、视觉标准和单页设计规格之间存在重复；
2. 教学诊断、选择建议单、设计卡、功能表和原型确认重复表达相同决策；
3. “自动演示”与近期学生主动推进的交互基线口径不一致；
4. 五区信息职责与三栏视觉布局的关系不够明确；
5. 缺少统一的规范权威顺序、任务风险分流和例外审批方式；
6. 验收要求偏重且容易重复，需要保留物理与教学底线，同时减少形式化检查。

## 5. 学生产品定位

动画直接服务高中生。学生应在没有教师讲解、完全静音的情况下知道：

1. 当前研究什么；
2. 从哪里开始；
3. 当前应做什么；
4. 重点观察哪里；
5. 如何验证结果；
6. 最后形成什么物理结论或二维模型。

页面不得显示开发术语、内部版本信息、审批信息或面向Codex的规则。教师和Codex使用的制作规范不直接暴露在学生界面中。

## 6. 精简后的五阶段流程

### 阶段一：任务审查

确认：

- 目标文件；
- 锁定元素；
- 唯一主教学目标；
- 最多一个直接服务主目标的辅助目标；
- 已有成果；
- 本轮修改边界；
- 版本策略；
- 任务属于新动画、重大改版、增量修改还是明确小修复。

### 阶段二：制作决策

将原教学诊断、选择建议单、设计卡和功能表合并为一份《制作决策单》，包含：

- 学习障碍和主目标；
- 两到四个有明显差异的方向，仅用于新动画或需要重新选择教学方向的重大改版；
- AI推荐及取舍；
- 是否拆分；
- 2D、2.5D、3D或组合形式；
- 三个左右核心功能；
- 两到四个主要可调参数；
- 主观察关系；
- 图像取舍；
- 必须、可选、不做、后续拓展；
- 如果必须删除一项功能，优先删除什么；
- 核心视觉锁定项。

教师确认《制作决策单》后才能进入下一阶段。

### 阶段三：模型与原型

合并物理模型校验与低成本原型，验证：

- 研究对象、坐标系、正方向、公式、单位；
- 参数合法范围、状态转换、临界条件和约束失效；
- 极端参数结果；
- 页面信息结构；
- 关键物理状态；
- 引导演示步骤；
- 每一步的主要观察焦点；
- 学生手动操作、`替我操作`和步骤完成条件。

复杂新动画和重大改版需要教师确认原型。已有项目的明确增量修改和小修复不强制单独制作原型。

### 阶段四：正式制作

在确认范围内增量完成：

- 物理内核；
- 实验状态；
- 教学脚本；
- 正式交互；
- 引导演示；
- 正式模型、材质、光照和阴影；
- 矢量、轨迹、图像和数据；
- 页面外壳和响应式；
- 性能优化。

设计确认后出现的新功能只能作为新增建议提出，不得直接加入。

### 阶段五：验证交付

完成一次最低验收，修复后只对受影响功能做定向复查，并快速走一次主流程。最终输出精简《验收交付报告》。

## 7. 按任务风险分流

### 新动画或重大改版

完整执行五阶段流程。改变主目标、核心交互、物理模型、视觉语言或响应式骨架时，自动视为重大改版。

### 已有动画增量修改

执行现状审查、修改决策、实现和验证。已有教学方向已经锁定时，不重复提出两到四个创意方案。

### 明确小修复

执行问题定位、最小修改和定向验证，不要求重新输出完整教学提案或原型。

## 8. 功能和信息预算

默认预算为：

- 一个主教学目标；
- 最多一个辅助目标；
- 三个左右核心功能；
- 两到四个主要可调参数；
- 每一步一个主要观察焦点；
- 主场景最多同时突出两组核心物理信息；
- 默认零到一张主图；
- 有明确对比任务时最多同时显示两张图；
- 一个默认折叠、可跳过的轻量验证模块。

任何功能、参数、图像或面板无法说明其服务的教学目标时，默认不加入。

## 9. 统一页面设计语言

页面从上到下保持以下教学层级：

1. 顶部品牌标题栏，只显示返回预留位、品牌和教学主题；
2. 主舞台上方的引导入口区，放置一个或多个引导演示情境按钮和实验指南按钮；
3. 主动画舞台，承载物理过程、当前阶段、重点观察、引导卡和重点光晕；
4. 主舞台内部最下方的物理时间控制条；
5. 宽屏左右参数/观察区，或窄屏、短横屏的单活动面板。

需要速度控制的动画，播放、暂停、`0.25×`、`0.5×`、`1×`、`2×`、必要观察范围和重置统一位于主舞台内部最下方，不放入参数栏、观察栏或引导卡。

页面外壳和教学组件完全统一。物理舞台内部允许使用题型需要的专属材质、真实颜色和空间环境；力、速度、轨迹、正确、警告等语义色继续统一。

## 10. 学生主导的“引导演示”

项目统一使用名称“引导演示”，不再使用容易导致自动跨步实现的“自动演示”。

引导演示定义为：由学生掌控阅读、观察、操作和推进节奏的分步学习模式。系统不得通过定时器自动触发操作或自动进入下一步。

### 10.1 步骤规则

- 学生首次选择某个引导演示情境或主动重新开始时，系统进入确定的教学初态；点击继续引导时不得重置；
- 观察步骤由学生阅读和观察，学生主动点击下一步；
- 观察步骤不显示`替我操作`；
- 操作步骤允许学生自己完成，也允许学生主动点击`替我操作`；
- 当前真实完成条件未满足时，下一步保持禁用；
- 学生自己完成和`替我操作`完成均由同一真实状态解锁下一步；
- `替我操作`只完成当前一步，不自动完成后续步骤；
- 上一步使用确定状态或同一物理内核重建；
- 关闭引导卡只隐藏引导，不重置物理状态、参数、预测、步骤或结果；
- 继续引导恢复原步骤和引导卡位置；
- 最后一步提供“现在自己试试”，从确定初态进入自由探索；
- 错误或条件不满足时停留在当前步骤并提供可恢复说明。

### 10.2 浮动引导卡

引导卡继续遵守视觉标准中的通用浮动引导卡：

- 默认位于主舞台下方中央、舞台控制条上方；
- 只允许从六点手柄或标题空白区拖动；
- 正文、为什么、关闭和操作按钮不触发拖动；
- 卡片只能在内容安全区内移动；
- 拖动、步骤变化、播放暂停、展开为什么、面板切换和尺寸变化均保留并夹取位置；
- 恢复默认布局或开始全新任务时回到默认位置；
- 拖动只改变位置，不改变学习或物理状态。

### 10.3 `替我操作`

- 只能由学生主动点击；
- 只在确有真实操作、参数设置或计算任务的步骤出现；
- 调用与学生手动操作相同的动作函数、物理内核和状态更新；
- 执行中显示正在操作；
- 真实完成条件满足后显示操作完成并解锁下一步；
- 不允许建立第二套伪动画或直接写入显示结果。

## 11. 紫色重点观察光晕

- 每一步原则上只突出一个联合重点区域；
- 使用项目关注紫色，中心边框最浓，向外形成多层逐渐变淡的光晕；
- 光晕采用柔和呼吸变化，由内向外扩散、由浓到淡，不采用生硬开关式闪烁；
- 保持到本步完成或切换步骤；
- 光晕层必须`pointer-events:none`；
- 不额外显示“重点观察”悬浮标签，引导卡中的“重点看”承担文字说明；
- 不给多个零散对象分别套框，相关对象合并为一个重点区域；
- 页面不提供“减少动态效果”按钮；
- 自动响应`prefers-reduced-motion`，只取消呼吸扩散，保留静态紫色边框和渐淡光晕；
- 必要物理运动不因减少动态设置而停止。
- 除必要物理运动外，统一页面不增加其他循环装饰动态；紫色重点光晕是项目唯一通用的循环提示动效。

## 12. 统一实现架构和状态流

动画可以使用单HTML或多个模块文件，但逻辑上必须区分：

1. 物理内核；
2. 唯一实验状态；
3. 教学步骤脚本；
4. 场景、矢量、图像、数据和二维模型显示模块；
5. 学生操作与`替我操作`共用的动作模块；
6. 标题、入口、布局、引导卡和指南构成的页面外壳。

统一数据流为：

学生操作或`替我操作`
→ 校验参数和步骤权限
→ 更新唯一实验状态
→ 物理内核计算
→ 所有显示模块同步刷新
→ 检查当前步骤真实完成条件
→ 解锁下一步。

硬性要求：

- 主场景、图像和引导系统不得各自维护物理结果；
- 不为引导演示建立第二套伪动画；
- 播放倍速只改变观看推进速度，不改变轨迹、临界状态和计算结果；
- 面板切换、关闭引导、窗口调整和转屏不得重置实验状态；
- 参数必须标明实时生效或修改后重新运行；
- 恢复默认布局只重置界面布局；重置实验才允许重置物理状态。

## 13. 公式排版

公式排版纳入视觉标准并作为硬性要求。规则按 DOM、原生 MathML、Canvas 和 SVG 分路径执行，且必须配有正确/错误示例和正向/反向文档契约。

- 简单行内公式根字号不低于 T5 `12px`；含标准分式、根式或多层脚本的核心/展示公式根字号不低于 T2 `16px`。HTML、Canvas、SVG 手工排版的角标、分子、分母和可见字形不低于 `11 CSS px`；原生 MathML 的浏览器内部层级缩放享有例外，但 `<math>` 根字号和代表尺寸可读性仍须验收。
- 删除全局 `sub, sup { font-size: 1em; }`。HTML 角标仅在公式作用域内缩放；禁止用全局覆盖、整体缩放或栅格化规避字号和数学排版。
- 凡斜杠承担数学除法语义，一律使用上下分子、分母和水平分数线的标准分式（MathML 为 `<mfrac>`）。普通斜杠仅可作为正体单位字符串的一部分，如 `m/s`、`m/s²`、`kg/m³`、`N/C`、`V/m`；多重单位除法必须用括号或负指数消歧。
- 每个角标绑定一个明确的底数节点。MathML 分别用 `<msub>`、`<msup>`、`<msubsup>` 表示下标、上标和配对角标；指数作用于复合量时，先以 `<mrow>` 建立完整底数；矢量上方箭头使用 `<mover accent="true">`，再绑定角标。变化符号与变量拆为独立 token，例如 `<mi mathvariant="normal">Δ</mi><mi>v</mi>`，禁止 `<mi>Δv</mi>`。
- 单字符物理变量使用数学斜体；数字、单位、函数名和描述性缩写使用正体。数值与单位之间使用不换行间距，二者不得拆行；同一动画中的矢量记法统一。
- Canvas 按 CSS 像素用 `measureText()` 计算文字 run、基线、分子、分母和分数线，DPR 只缩放 backing store；SVG 以独立 `<text>/<tspan>` 或等价节点显式定位。两者都必须与同一物理状态同步生成 DOM 等价文本和完整可访问名称；SVG 至少使用 `<title>` 和 `aria-labelledby`，Canvas 使用邻近或 fallback DOM 文本。

## 14. 实验装置视觉品质

核心实验装置的模型、材质、光照、阴影和空间层次属于锁定的正式品质，不得因布局调整、增加引导或性能优化发生可感知降级。

要求：

- 核心装置保持体积感、接触阴影、前后关系和结构边缘；
- 重点照明帮助学生辨认装置结构和物理过程；
- 不得出现扁平、发灰、过曝、欠曝或材质无法区分；
- 性能不足时优先减少非核心对象、背景装饰、无关特效和不可见计算；
- 改版前后生成并保存同尺寸截图，人工对比并核对核心装置的模型、材质、光照、阴影和空间层次；该对比是最低验收的留存证据；
- 已达到较高品质的装置默认视为锁定成果，除非教师明确要求重新设计；
- 品质、性能和范围冲突时，优先缩减非核心范围并向教师说明。

## 15. 一次最低验收与定向复查

每个版本只进行一次完整最低验收，确认：

1. 物理公式、单位和核心结果正确；
2. 页面正常打开，核心引导演示能够走通；
3. 不存在阻断操作、状态错乱、无法继续等严重Bug；
4. 不存在引导卡、面板或控件大面积遮挡主要观察对象；
5. 关键横屏尺寸下没有横向溢出和无法点击的按钮；
6. 控制台没有影响运行的严重错误；
7. 不存在音频资源、控件、接口或预留代码；
8. 核心实验装置视觉品质未下降。

最低验收使用少量关键编号：

- `EDU`：单一目标、单一观察焦点和静音自主学习；
- `PHY`：公式、单位、状态转换、临界条件和倍速不改变结果；
- `GUIDE`：学生推进、学生触发`替我操作`、真实状态门控、恢复状态和卡片安全拖动；
- `VIS`：标题、入口、舞台控制条、字号、触控、公式和光影品质；
- `RESP`：宽屏、横屏平板、窄屏和短横屏布局。

代表尺寸为：

- `1180×820`；
- `1024×768`；
- `960×768`；
- `960×540`；
- `390×844`只进行窄屏基本可用性检查，不作为主要教学设备标准。

修复后只定向复查受影响功能，并快速走一次主流程，不重复执行全部验收。轻微间距和非关键装饰问题不阻止交付，可进入后续人工反馈。

## 16. 人工反馈与增量修改

最低验收后由教师或学生进行人工体验：

1. 记录明确问题和出现条件；
2. Codex只修改相关模块；
3. 定向复查修改项；
4. 快速执行主流程冒烟测试；
5. 不借修复扩大范围或整体重写。

最终交付报告只说明：

- 修改文件；
- 保留内容；
- 实现内容；
- 明确未做内容；
- 测试结果；
- 已知限制；
- 需要教师确认的偏离。

## 17. 明确不做

- 不批量重做未进入任务范围的旧动画；
- 不建立账号、班级、云端档案或复杂评分系统；
- 不加入或预留声音；
- 不让每个动画自行发明新的页面外壳、引导卡或步骤推进逻辑；
- 不要求小修复重复完整教学策划流程；
- 不以消除所有轻微视觉问题为交付前提；
- 不因执行新规范整体重写已验证的物理模型或高品质实验装置。

## 18. 成功标准

统一规范完成后，新的Codex进入项目只需读取`AGENTS.md`指向的两份仓库内规范，即可清楚知道：

- 当前任务是否需要提案和教师确认；
- 动画如何围绕一个主教学目标做减法；
- 学生如何通过引导演示自主学习；
- `替我操作`为何不能自动触发；
- 页面入口、舞台、速度控制和面板如何组织；
- 物理状态如何成为唯一数据源；
- 公式、重点光晕和实验装置光影如何呈现；
- 何时只做最小修复，何时升级为重大改版；
- 如何用一次最低验收和人工反馈完成交付。
