# 物理动画持续反馈与标准升级机制设计

- 日期：2026-08-11
- 状态：教师已确认，持续反馈机制已实施并通过文档契约验证
- 适用项目：动画制作
- 方案：双层活标准

## 1. 背景与目标

项目已经建立 `AGENTS.md`、`docs/物理动画统一制作规范-v1.md` 和 `docs/物理动画视觉标准-v1.md` 三层权威。后续所有新建、改版和修复任务都必须遵守 `main` 中的最新版本；同时，教师在查看实际动画后可以随时提出不满意之处并继续调整。

本机制解决两个问题：

1. 确保后续 Codex 不会绕过统一标准；
2. 区分“只修改当前动画”和“以后所有动画都执行”的反馈，防止题型特例误变成全项目规则，也防止通用确认停留在口头对话中。

## 2. 核心原则

- 默认把教师反馈解释为当前动画调整，不自动推广到全项目。
- 只有教师明确表达“以后都这样”“升级为项目标准”或同等含义，才进入标准候选流程。
- 标准候选先在当前动画中验证实际效果；教师确认效果后，才形成正式标准条文。
- 教师最新明确确认高于旧规则；涉及项目红线变化时，Codex 必须指出冲突和影响，再等待明确确认。
- 教师可以反复提出调整，没有轮数限制；每轮只做受影响功能的定向复查和一次主流程冒烟，不重复完整最低验收。
- 标准更新只约束后续新任务和以后再次修改的旧动画，不触发旧动画批量迁移。

## 3. 两层反馈模型

### 3.1 当前动画调整

适用于“这里改一下”“这个动画我不满意”等未明确要求推广的反馈。

- 只修改当前目标文件及其直接相关测试、说明或资源；
- 保留教师已经锁定的物理模型、视觉品质、交互和数据结构；
- 采用增量修改，不重新启动完整策划流程；
- 修改后只定向复查受影响功能并快速走一次主流程；
- 不修改全项目三份权威文件。

### 3.2 全项目标准升级

适用于教师明确表达“以后都这样”“升级为项目标准”或同等含义的反馈。

标准升级分为三个状态：

1. **标准候选**：当前动画正在验证该做法，尚不约束其他任务；
2. **教师确认**：当前动画效果已满足要求，教师确认适用于后续动画；
3. **正式生效**：条文、契约测试和版本记录通过审查并合并进 `main`。

在第三个状态完成前，其他 Codex 不得把候选做法当成项目强制标准。

## 4. Codex 反馈响应协议

教师每次提出不满意或调整意见后，Codex 在动手前用简短文字复述：

- 理解到的不满意点；
- 本轮属于当前动画调整还是全项目标准候选；
- 将影响哪些页面、模块或规范；
- 哪些锁定内容不会改变；
- 修改后的定向验证范围。

自然语言判定示例：

- “这个动画这里改一下” → 当前动画调整；
- “以后都这样” → 全项目标准候选；
- “这部分锁定” → 后续未经明确解除不得改变；
- “取消以前那条要求” → 标准修订或回退候选；
- 语义不明确 → 默认当前动画调整，必要时只询问范围，不自行推广。

## 5. 权威文件职责

- 教学目标、五阶段流程、学生操作、唯一真实状态、验收和反馈流程变化：更新 `docs/物理动画统一制作规范-v1.md`。
- 颜色、布局、字号、公式、光晕、引导卡、触控和响应式变化：更新 `docs/物理动画视觉标准-v1.md`。
- 所有动画必须遵守的必读入口和项目红线：更新 `AGENTS.md`。
- 只适用于当前题型的特殊规则：写入当前动画的制作决策或修改说明，不进入全项目规范。

任何一条规则只能有一个详细权威来源；`AGENTS.md` 只保留入口和红线，不复制视觉或流程实现细节。

## 6. 标准升级流程

教师确认将反馈升级为项目标准后，依次执行：

1. 确定规则归属、适用范围、与旧规则的关系和回退边界；
2. 修改唯一权威文件；
3. 更新文档契约测试，防止后续回退或职责漂移；
4. 记录变更原因、教师确认和版本影响；
5. 运行定向契约与仓库全量回归；
6. 通过 Pull Request 复核并合并进 `main`；
7. 合并后，后续 Codex 才以新规则作为强制基线。

撤销或修改既有项目标准时走同一流程，不直接删除历史规则而不说明替代关系。

## 7. 验证与人工反馈

### 当前动画调整

- 不重复完整最低验收；
- 定向检查受影响交互、物理结果、布局和视觉品质；
- 快速走一次主流程；
- 需要视觉判断时提供同尺寸前后截图；
- 教师不满意则继续下一轮增量修改。

### 全项目标准升级

- 新增或修改对应契约断言；
- 运行全部统一规范契约；
- 运行仓库全量测试；
- 检查三份权威文件职责边界和旧称、旧依赖；
- 完成独立审查后才允许合并。

## 8. 项目正式生效

本机制实施后追加到现有 PR #1：

1. 在统一制作规范增加“教师持续反馈与标准升级”章节；
2. 在 `AGENTS.md` 增加反馈范围判断红线；
3. 在统一规范契约中增加当前调整与标准升级边界；
4. 更新并推送 `codex/unified-animation-standards`；
5. 审查通过后合并到远端 `main`；
6. 安全同步本地项目，保留主工作区现有未提交草案和 `outputs/`，不得直接覆盖或清理。

完成合并和本地同步后，在动画制作项目中启动的所有 Codex 都必须先读取 `main` 中的最新版三份权威文件。

## 9. 非目标

- 不建立复杂审批系统、账号权限或在线配置中心；
- 不要求教师使用固定格式指令；
- 不为每个动画建立独立标准体系；
- 不因标准升级批量重做旧动画；
- 不把一次题型特例自动推广为全项目规则；
- 不因反复反馈降低物理正确性、装置光影品质或学生可操作性。

## 10. 验收标准

- 任一后续 Codex 都能从 `AGENTS.md` 找到两份仓库内权威规范；
- 教师反馈未明确推广时，Codex 只修改当前动画；
- 教师明确“以后都这样”时，Codex先验证当前动画，再提出标准条文；
- 标准只有在规范、契约测试、版本记录和 PR 全部完成后才正式生效；
- 每轮动画调整只做定向复查和主流程冒烟；
- 规范升级后不会自动批量迁移旧动画；
- 本地主工作区现有未提交内容在同步过程中得到保留。
