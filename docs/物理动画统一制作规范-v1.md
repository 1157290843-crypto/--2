# 物理动画统一制作规范 v1.1

## 0. 标准身份、适用范围与权威顺序

本文是本项目新建、改版和修复物理动画时关于教学、制作流程、交互状态、范围和验收的唯一权威，服务教师、Codex、设计与开发人员。目标是让高中生在完全静音、没有教师讲解时，能够知道研究什么、从哪里开始、做什么、看哪里，并形成什么结论。

冲突时依次遵从：教师对当前任务的明确确认（项目红线变更须明确确认）、`AGENTS.md` 的项目红线、本文、`docs/物理动画视觉标准-v1.md`、当前动画已确认设计、历史实现。本文只规定职责和流程；视觉标准负责颜色、尺寸、公式排版、触控、响应式和引导卡的具体实现。偏离本文或视觉标准必须列出偏离项、教学必要性与影响，并取得教师确认。

## 1. 学生产品定位

动画面向高中生横屏平板自主学习，是可操作、可观察、可验证的物理模型，而非普通视频。每个动画围绕一个具体概念、模型、实验问题、关键过程或易错点；学生应能经历预测、设置条件、操作、观察、对比、验证并迁移到二维物理模型或解题思路。

教学引导只使用文字、聚焦、提示、关键暂停和分步反馈。全项目无声音，不加入或预留配音、音乐、音效、语音按钮、音量控件、音频资源或接口。

## 2. 启动信息与任务风险分级

教师必须提供目标文件、锁定元素、本轮唯一主教学目标和修改边界，并说明已有成果与版本策略；未指定版本策略时，保留原文件并生成递增版本。

- 新动画或重大改版：改变主目标、核心交互、物理模型、视觉语言或响应式骨架时，完整执行五阶段。
- 已有动画增量修改：先审查现状，再完成相关决策、实现和验证；教学方向未变时不重复提出多个创意方案。
- 明确小修复：只做问题定位、最小修改和定向验证，不升级为完整策划或原型。

## 3. 五阶段制作流程

### 阶段一：任务审查

核对输入信息、已有页面和物理模型，界定锁定元素、修改边界、版本策略及风险等级。确认一个主教学目标、最多一个直接服务它的辅助目标、学生学习障碍、预期结论和是否应拆分为多个动画。

### 阶段二：制作决策

形成一份《制作决策单》，合并历史教学诊断、选择建议单、设计卡和功能表。它记录学习障碍、目标、物理模型、表现形式、观察关系、核心功能、参数、图像取舍、核心视觉锁定项，以及“必须、可选、不做、后续拓展”和优先删除项。

仅新动画或重新选择教学方向的重大改版，提出二至四个明显不同方案，给出 AI 推荐、理由、认知负担、开发代价和取舍；教师确认《制作决策单》后才进入下一阶段。

### 阶段三：模型与原型

以低成本原型校验研究对象、坐标系、正方向、公式、单位、参数范围、状态转换、临界条件、极端结果、页面信息职责与关键物理状态。写清引导演示步骤、每步观察焦点、手动操作、完成条件和替我操作路径。复杂新动画和重大改版须由教师确认原型；已有项目的增量修改和小修复不强制另做原型。

### 阶段四：正式制作

在确认范围内增量完成物理内核、实验状态、教学脚本、交互、引导演示、装置表现、数据与页面外壳。确认后产生的新功能只能作为建议等待确认，不能直接加入。性能优化先删减非核心范围，不能改变已锁定的核心品质。

### 阶段五：验证交付

完成一次最低验收，整理版本、截图、定向验证记录和精简验收交付报告。教师或学生人工体验后的反馈，只增量修改相关模块。

## 4. 教学目标、功能预算与主动做减法

默认预算是一个主教学目标、最多一个辅助目标、三个左右核心功能、二至四个主要参数、每步一个主要观察焦点、主场景最多两组高亮信息和零至一张主图；有明确对比任务时才可同时使用两张图。

每项功能、参数、图像、面板、按钮、数据或特效都要说明服务哪个教学目标、帮助学生做什么、删除后是否影响主线、是否重复、是否增加独立目标。无法说明时默认不加入；折叠、隐藏或页签不是保留堆砌内容的理由。制作决策单必须明确只能保留的三个核心功能，以及若必须删除一项时优先删除什么。

## 5. 物理模型、参数分类与唯一实验状态

逻辑上分离物理内核、唯一实验状态、教学脚本、显示模块、动作模块和页面外壳；主场景、图像、引导与数据不得各自保存物理结果。参数须标明实时生效或修改后需重跑。物理时间与观看倍速分离，倍速不改变轨迹、临界状态或计算结果。

学生手动操作和替我操作均通过同一动作更新唯一实验状态，再由物理内核计算并同步全部显示。统一路径是：校验参数和步骤权限、更新状态、物理计算、同步显示、检查真实完成条件、解锁下一步。面板切换、窗口调整、转屏、关闭引导和恢复引导不得重置实验状态；恢复默认布局只重置布局，实验重置才可重置物理状态。

## 6. 2D、2.5D、3D与核心视觉品质

根据教学目标、空间认知需要、物理过程和学生操作选择 2D、2.5D、3D 或组合，不以实现难度决定。空间结构、空间运动或场分布需要时优先评估 3D；平面运动但需要空间层次时可采用 2.5D；受力图、电路图、光路图、函数图像和推导通常优先 2D。

核心实验装置的模型、材质、光照、阴影和空间层次是锁定的正式品质。性能或范围冲突时，先删非核心对象、装饰、特效和不可见计算，不得以布局、引导或性能为由造成可感知降级；必要时建议缩小范围、分阶段交付或调整技术以保持教学效果和可感知品质。原型可用占位表现，但不得作为正式版本交付。

改版前后生成并保存同尺寸截图，人工对比并核对核心装置的模型、材质、光照、阴影和空间层次。

## 7. 学生主导的引导演示

项目只使用“引导演示”；学生主动点击下一步，系统不得通过定时器自动操作或自动跨步。引导卡遵守视觉标准的通用浮动引导卡。

### 7.1 学生主动推进

学生选择情境或主动重新开始时进入确定教学初态。阅读、观察、操作和推进节奏均由学生掌握；错误或条件不满足时停留当前步骤，给出可恢复的文字反馈。

### 7.2 观察步骤与操作步骤

观察步骤由学生阅读和观察后主动下一步，观察步骤不显示替我操作。操作步骤允许学生亲手完成，并以真实完成条件门控下一步；未满足条件时下一步保持禁用。

### 7.3 替我操作

替我操作只能由学生主动点击，只完成当前一步。它与学生手动操作共用同一动作模块、唯一实验状态和物理内核；仅在真实完成条件满足后解锁下一步。不得建立第二套伪动画，不得直接写入显示结果，也不得自动完成后续步骤。

### 7.4 关闭、继续、上一步与自由探索

关闭引导只隐藏卡片并保留实验状态；继续引导恢复原步骤和卡片位置；上一步以确定状态或同一物理内核重建；“现在自己试试”从确定初态进入自由探索。拖动、步骤变化、播放暂停、面板切换和尺寸变化均保留学习状态与卡片位置。

## 8. 页面信息职责与视觉标准引用

统一页面只规定标题、入口、舞台、舞台底部控制及参数/观察区域的职责：标题说明教学主题，入口启动引导演示或指南，舞台承载核心现象和当前重点，舞台底部控制服务物理时间，参数区设置条件，观察区呈现数据、结论和二维模型。颜色、尺寸、公式和光晕实现以视觉标准为准；具体品牌、字号、触控和响应式布局同样只引用视觉标准。

## 9. 已有项目、版本与例外审批

已有项目优先增量修改和模块复用，不因执行本规范批量重做旧动画、重写已验证物理模型或高品质装置。新版本保留原文件并按策略递增；交付物应标明目标文件、修改范围、版本与验证证据。

例外必须先由教师确认：列出偏离的规范项、教学必要性、对物理、学习、视觉和维护的影响及回退边界。旧页面或历史做法不能自动构成例外。

## 10. 一次最低验收、人工反馈与交付

每个版本只进行一次完整最低验收；修复后只定向复查受影响功能，并快速走一次主流程冒烟。人工体验提出反馈后，继续增量修改相关模块，不重复整套验收。

| 编号 | 最低验收内容 |
|---|---|
| `EDU` | 单一目标、单一观察焦点和静音自主学习。 |
| `PHY` | 公式、单位、状态转换、临界条件和倍速不改变结果。 |
| `GUIDE` | 学生推进、学生主动触发替我操作、真实状态门控、恢复状态和卡片安全拖动。 |
| `VIS` | 标题、入口、舞台控制条、字号、触控、公式及装置光影品质。 |
| `RESP` | 宽屏、横屏平板、窄屏和短横屏布局。 |

代表尺寸逐项检查：`1180×820`、`1024×768`、`960×768`、`960×540`、`390×844`。其中 `390×844` 只做窄屏基本可用性检查，不作为主要教学设备标准。与 `VIS` 验收一并保存上述代表尺寸的截图证据；改版时还保存用于核心装置人工对比的同尺寸截图。

交付包括递增版本文件、制作决策单或修改说明、最低验收结果、定向复查记录、主流程冒烟结果和截图证据。

## 11. 教师持续反馈与标准升级

教师可以在查看实际动画后随时提出不满意和调整意见，没有反馈轮数限制。反馈未明确要求推广时，默认只修改当前动画，不自动改变全项目标准。

### 11.1 当前动画调整

“这个动画这里改一下”等反馈只影响当前目标文件。Codex 动手前简短复述不满意点、影响范围、不会改变的锁定内容和定向验证范围；修改采用增量方式，不重新启动完整策划。每轮不重复完整最低验收，只定向复查受影响功能并快速走一次主流程冒烟。需要视觉判断时提供同尺寸前后截图；现有资料不足时，直接向教师说明还需要的截图和想法。

### 11.2 全项目标准候选

教师明确表达“以后都这样”“升级为项目标准”或同等含义时，该反馈才进入全项目标准候选。候选先在当前动画中验证；教师确认当前动画效果后，Codex 再整理正式条文、适用范围、与旧规则的关系和回退边界。

### 11.3 规则归属与正式生效

教学流程、学生操作、唯一状态和验收变化写入本文；颜色、布局、字号、公式、光晕、引导卡、触控和响应式变化写入视觉标准；项目必读入口和红线写入 `AGENTS.md`；题型特例只写当前动画的制作决策或修改说明。

教师最新明确确认高于旧规则，并可以发起对旧规则的修订；涉及项目红线变化时，Codex 必须先说明冲突和影响，取得教师明确确认后再继续。

全项目规则必须同步更新唯一权威文件、契约测试和版本记录，完成定向验证与仓库全量回归，并通过 Pull Request 合并进 `main` 后才正式生效。在合并前，其他 Codex 不得把候选做法当作强制标准。

标准升级不批量迁移旧动画；旧动画以后再次修改时才应用最新版。撤销既有标准时走同一确认、测试和合并流程，并说明替代关系。

## 12. 明确不做

- 不批量重做旧动画。
- 不建立账号、班级、云端档案或复杂评分系统。
- 不把明确小修复升级为完整策划。
- 不因执行新规范重写已验证物理模型或高品质装置。
- 不增加与主教学目标无关的功能、参数、图像、面板或装饰。
